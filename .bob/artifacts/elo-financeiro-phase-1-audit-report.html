Security

#SeverityFindingLocation
S1CRITICALNo input length or type guard on scenario name. set_scenario(payload.get("name")) passes the raw browser-supplied string directly to load_scenario(). A non-string (e.g. null, a dict) will produce an unhandled TypeError; the 400 handler catches it but the error message is generic and the intent is never checked. The name should be validated as a non-empty string ≤ 40 chars before lookup.server.py:179
S2CRITICALMissing Secure flag on session cookie. The Set-Cookie header uses HttpOnly; SameSite=Strict but omits Secure. When deployed behind HTTPS (required for Phase 5), the cookie will still be transmitted in plain HTTP if any redirect is involved. Add ; Secure unconditionally — it is harmless on localhost and required for production.server.py:135
S3CRITICALNo HTTPS enforcement on the watsonx.py URL-open calls. urlopen does not verify hostname against the trusted CA store by default in older LibreSSL builds. For the IAM token endpoint and the watsonx endpoint, an explicit ssl.create_default_context() should be passed so certificate validation is guaranteed regardless of the Python/OpenSSL build.watsonx.py:24-27
S4CRITICALSession count limit uses a dictionary check that is not atomic under concurrency. The check if len(sessions) >= 100 followed by the insert happens inside sessions_lock, so it is actually safe today. However, get_session() instantiates DemoSession inside the lock, which runs build_report (including file I/O) while holding the global sessions lock — this serializes all request threads and can cause a timeout-based DoS. Session construction should happen outside the lock.server.py:118-125
S5IMPORTANTPrompt-injection risk in the watsonx prompt. The scenario snapshot is appended with string concatenation after a "CONTEXTO:" marker. An adversarial synthetic scenario with embedded instructions could attempt to override the task. Use a structured message format (e.g. JSON with separate system and user fields) if the model API supports it, or at minimum add a separator and re-state the constraint after the context block.watsonx.py:28-33
S6IMPORTANTXSS vector: no rel="noopener" fallback in CSP. The CSP header is solid but app.js sets a.target="_blank" and a.rel="noopener noreferrer" dynamically for guidance links. If knowledge.json ever contains a javascript: URL it would be rendered in an anchor. The server should strip non-HTTP(S) URLs from knowledge.json documents before serving them, or validate URLs server-side.core.py:116, app.js:90
S7IMPORTANTNo CORS response headers at all. The Origin check rejects cross-origin POSTs (good), but there are no Access-Control-Allow-* headers on any response. This is fine for a same-origin demo but must be documented; adding explicit Access-Control-Allow-Origin: <origin> rejection (or a vary: Origin header) is needed before public deployment.server.py:127-137
S8IMPORTANTContent-Length is trusted without capping at parse time. The code reads Content-Length, rejects values outside 0–8192, then calls self.rfile.read(size). If the header is absent (default 0) the condition not 0 < size raises a 400, but if a client sends a legitimate header value of 8193 or a non-integer value, the int() call will raise ValueError, which is silently caught and returns "requisição inválida". This is correct but the intent should be explicit — validate that Content-Length is a valid positive integer before parsing.server.py:169-172

Bugs

#SeverityFindingLocation
B1CRITICAL (logic)Consent check uses is not True, which accepts any truthy non-boolean. build_report guards on consent is not True. But set_consent validates type(enabled) is not bool before storing, so only True/False can reach the report. Consistent, but the HTTP layer passes payload.get("enabled") without a type guard before calling set_consent — if enabled is missing the dict key, it passes None, which correctly raises ValueError (wrong type). Edge case is safe, but the guard should be documented.server.py:178
B2IMPORTANTnew_cookie attribute leaks between requests on the same thread. self.new_cookie is set on the handler instance; BaseHTTPRequestHandler creates one instance per request, so this is safe today. But it is a fragile pattern — if the server is refactored to reuse handler instances, the cookie would be re-sent on every subsequent request from that handler. Prefer passing the cookie value explicitly through send_bytes.server.py:124, 134
B3IMPORTANTflexible field on events is not validated in validate(). The validate() function checks direction, date, and amount but not whether the flexible field is a boolean. A scenario with "flexible": 1 passes validation, and apply_saving checks event.get("flexible", False) — 1 is truthy, so it would pass. The scenarios.json is controlled, but the field should be typed.core.py:29-46
B4IMPORTANTguidance() reads knowledge.json on every call — no caching. The file is read and JSON-decoded on every single request. For a demo this is fine, but it is a correctness hazard too: if the file is being written while the server is running, a partial read would crash. Should be loaded once at startup, like CATALOG.core.py:114
B5IMPORTANTREADME says cd elo-financeiro-bb but the repo directory is elo-financeiro. The pyproject.toml name is elo-financeiro-bb, but the workspace root is elo-financeiro. The quick-start command in the README will fail for any evaluator who clones the repo and follows it literally.README.md:21
B6IMPORTANTapp.js crashes on non-cashflow reports (consent not yet given). The render() function returns early when !state.consent — correct. But the initial request("/api/state") returns a report with status: "consent_required" and no results key, so if render() ever falls through to const flow = report.results.cashflow without the guard, it throws. The guard is present but fragile; the workspace-hidden block should also null-check report.results.app.js:39

Test Gaps

#SeverityFinding
T1IMPORTANTNo test for zero balance. balance_cents: 0 with upcoming bills — the minimum would be immediately negative; not explicitly covered.
T2IMPORTANTNo test for multiple bills on the same day. The same-day test exists but uses one in/one out. A scenario with 3 outflows on the same day (all flexible) and apply_saving is not tested.
T3IMPORTANTNo test for delayed income (income date moved past horizon). The system should gracefully handle a scenario where no direction:"in" event falls within the horizon.
T4IMPORTANTNo test for approving a plan against stale data (via HTTP). test_changed_snapshot_requires_fresh_approval exists at the unit level but there is no HTTP-level test for the 400 response when report_id is stale.
T5IMPORTANTNo test for revoking consent mid-flow via HTTP. The unit test covers it, but no HTTP roundtrip test verifies the 403/400 cascade after a revoke POST.
T6IMPORTANTNo test for malformed watsonx output (non-JSON, JSON without tools key, tools list with unknown names, empty list, list of length 5). Only a RuntimeError fallback is tested.
T7NICEHTTP tests do not cover path-traversal for /api/* routes (e.g. /api/../../etc/passwd). The URL is split with urlsplit so this is safe, but coverage is absent.
T8NICENo test for the purchase scenario approval (purchase-goal action) via HTTP. The unit test for purchase impacted metrics exists, but the full HTTP flow is missing.

Accessibility (UI)

#SeverityFinding
A1IMPORTANTAll scenario buttons in the sidebar lack aria-label or unique accessible names. The buttons are generated dynamically with text content only; no aria-label and no grouping role tells a screen reader this is a navigation control. The containing <nav> has a label — good — but each button still needs a role hint such as "Selecionar cenário: [título]".
A2IMPORTANTThe "Simular nova despesa" button is not disabled after the event is simulated. The server returns a 400 if triggered twice, but the button stays enabled and clickable, confusing keyboard/AT users. The button should be disabled after the monitor event fires.
A3IMPORTANTError message (#error) uses role="alert" but is initially hidden. Setting hidden on a live region prevents AT from announcing updates when it becomes visible in some browsers. Better practice: keep the element visible but empty, and populate it with text to trigger the announcement.
A4NICENo lang attribute on dynamically injected content. The <html lang="pt-BR"> is correct but inline SVG or future embedded charts won't inherit it. Minor — just keep it in mind for Phase 4.
A5NICEThe <details>/<summary> trace block has no aria-label. Its summary text is "Como o agente chegou…" which is descriptive enough, but adding an explicit id and linking the panel to its heading with aria-labelledby improves navigation for AT users.
A6NICEColor alone encodes negative balance (red class .negative). No icon or text annotation differentiates negative from positive values for color-blind users. An "(−)" prefix or a "⚠" symbol with an aria-label would address WCAG 1.4.1.
A7NICESidebar is not reachable via keyboard skip link. There is no "Skip to main content" link, so keyboard-only users must tab through all scenario buttons before reaching the main panel.
